# Q: Все равно есть ощущение что пираньи существуют меньше чем три заброса. Лучше: при появлении жертва недоступна, после следующего заброса доступна, а 0 — последний шанс?

## Answer

Expanded from original query via vocab: [piranhas, sacrifice, cast, turn, encounter]. Да: схема понятнее. Текущий код сохраняет появление вне расхода castsUsed, но разрешает жертву сразу и удаляет событие при достижении лимита в конце третьего следующего заброса, поэтому состояние 0 не становится доступным окном. Предлагаемый UX переносит три окна выбора на значения 2, 1, 0: при 3 показывается предупреждение и выбор заблокирован; после первого следующего заброса выбор открывается; при 0 событие остается до попытки еще одного заброса, перед которым исчезает. Это не увеличивает число фактических окон выбора, но делает счетчик интуитивным.
